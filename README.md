# AceScheduler

这是一个运行在用户侧的外部小工具。某些电脑游戏自带的安全防护组件会在运行期间乃至退出之后，继续在后台遍历磁盘文件、做哈希比对并上报结果，这段时间里磁盘 IO 与 CPU 的争抢会让前台程序明显卡顿。本项目的目标很克制：不阻止这些扫描，也不改变它们的功能，只是在扫描与前台程序发生资源冲突的时候，让扫描"让路"；并在确认扫描真正结束之后，第一时间把施加的限制完全归还。

工作方式是一个三态状态机。工具以固定节奏采样目标进程的累计读取字节数，连续两次超过阈值即判定进入扫描突发，随后把目标进程的 CPU 优先级压到最低并绑定到单个核心。限速持续若干秒后，工具会放开一个短暂的探测窗口再次测量速率：速率仍然很高说明扫描还在继续，回到限速；速率已经很低才判定扫描真正结束，恢复目标的原始优先级与完整核心可用性。设置探测窗口是因为这里有一个隐蔽的陷阱——限速本身会把目标的速率饿到接近零，单看速率会把"被饿死"误判成"扫完了"。沙盒闭环测试中，被限速的模拟扫描器在三秒钟内只分到三十一毫秒的处理器时间，而探测窗口一放开速率立即回弹，证明这套机制能区分"被饿死"与"真结束"这两种表面相同的低速率。

目前的进度：试用版以脚本形态完成了四阶段闭环验证，五项检查全部通过，争抢窗口内目标吞吐降到基线的 0.465 倍；生产版骨架已经用 C# 写好，并编译为自包含的单文件可执行程序，冒烟测试通过。接下来的计划有三件事：通过系统服务的安装事件自动发现目标进程，替代手工指定，做到零常驻；引入前台窗口判定，让"是否让路"取决于前台是否真的在抢资源；最后打包成可安装的程序，并处理分发环节的签名问题。

安全边界与既有的同类社区工具保持同一条线：只调用公开的系统接口调整资源分配（优先级、处理器亲和性、IO 优先级、效率模式），不向目标进程注入代码，不阻断任何网络连接，不修改任何其他软件的文件。越过这条线，"资源调度"就变成了"妨碍安全组件运行"，属于各类用户协议明确打击的行为。

免责声明：本项目与任何游戏厂商或安全厂商无关。调整第三方进程的优先级存在理论上的账号与系统风险，使用本工具产生的一切后果由使用者自行承担，项目仅供学习与研究。

构建与复现：试用版验证可用 PowerShell 运行 trial 目录下的 run-trial.ps1 复现；生产版需要 .NET 8 SDK，运行仓库根目录的 build.ps1 即可在 dist 目录得到单文件 exe。更完整的设计推导与机制分析见 docs 目录。
